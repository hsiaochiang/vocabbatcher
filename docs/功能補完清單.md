## (A) 壞掉或缺了就沒辦法用的 — 最優先

### A-1｜新增 Markdown parser rule：從 top2025.md 解析
**狀態：** 未做（現有 parser 讀 PDF，zh_definition / pos 全為 null）
**說明：** `top2025.md` 格式為 Markdown 表格，每行 `| **word** | [pos] | zh_definition |`，頻率從章節標題 `## 出現次數：N` 讀取。需要新增一個 parser rule（例如 `rules/top2025_md.py`）來解析這份 MD，取代目前的 PDF 流程，讓 `vocab.cleaned.json` 真正含有中文釋義與詞性。
**難易度：** 低至中（規律格式，regex 清晰，寫新 rule + 修改 CLI 入口，約 2–4 小時）
**實際影響：** **這項不做，App 的 TTS「唸中文」、翻牌卡背面、中翻英測驗全部無資料可顯示。這是進入 App 開發前必須完成的前置工作。**

---

### A-2｜parse_confidence 計算與規格不符
**狀態：** CRITICAL bug（code review 已記錄）
**說明：** 規格要求「只有 word、其餘欄位為 null」的記錄，confidence 應 ≤ 0.3。目前公式 `word(1.0) / total_weight(2.0) = 0.5`，超標。完成 A-1 後，MD 資料多數記錄會有 pos + zh_def，整體 confidence 分布會改變，但公式本身仍需修正。
**修改位置：** `src/pdf_parser/qa.py:14–39`、`tests/test_qa.py:26`
**難易度：** 低（調整權重分母，約 15 分鐘）
**實際影響：** QA 報告信心分數虛高，M1 驗收標準「parse_confidence ≥ 0.85 整體」的語意失真，但不影響日常執行。

---

### A-3｜解析失敗的行沒有被記錄成低信心項目
**狀態：** CRITICAL bug（code review 已記錄）
**說明：** 規格要求「無法解析的行：跳過，但記錄為低信心項目」。目前直接丟棄，QA report 低報了解析失敗數量。完成 A-1（MD parser）後，MD 的 50 筆缺 pos / 37 筆缺 zh_def 會正確產出 low-confidence 記錄，但解析完全失敗的行仍不會被追蹤。
**修改位置：** `src/pdf_parser/parser.py:58–70`
**難易度：** 低至中（加 rejected 計數器，約 30 分鐘）
**實際影響：** 不影響實際使用，但 QA 報告可靠性下降，parser 品質無法稽核。
