## 跨切片一致性（執行層務必遵守）

- 拼字填空判分規則（大小寫不敏感、去頭尾空白）只寫一處，M4-S1 建立在 `exam.ts`，之後其他題型/複習卷重用同一函式，不得各自複製判斷邏輯。
- M4-S2 串接「練習測驗」時，**不修改** `src/services/exam.ts` 既有頁碼範圍出題邏輯，只是從 `BatchHubPage` 帶預設參數過去，維持「全域考試」與「批次」是兩個獨立資料流（考試成績仍記在使用者帳號下，不綁定 batch id）。
- 沿用既有規則：`BrowserRouter` 不可改回 `HashRouter`；Workbox `navigateFallbackDenylist` 不可動；Firestore 新路徑要記得補規則（本階段預期不需新 collection）。
- UI/UX 相關切片（M4-S2、M4-S3、M4-S4）收工前依 `AGENTS.md` 規則用 Playwright 自我驗證。

## 驗收軌道 B（負責人把關，白話清單）

1. M4-S1：考試設定選「混合模式」，作答時會出現「打字輸入英文單字」的題目，答對/答錯都能正確判分。
2. M4-S2：進入任一批次頁，只剩三格（翻牌學習／練習測驗／學習統計），沒有「即將推出」的字樣；點「練習測驗」會直接帶你去考試設定頁且頁碼範圍已經幫你選好；點「學習統計」會看到單字統計頁。
3. M4-S3：進階搜尋打一個查不到的關鍵字，畫面有清楚的「查無結果」提示而不是空白；不選任何字直接想建立批次會被擋下；捲動整份 1231 字清單不會明顯卡頓。
4. M4-S4：用手機瀏覽器把每個主要頁面都點過一輪，沒有畫面整頁空白或整個 App 沒反應的狀況；`README.md` 讀起來一個沒碰過這專案的人能看懂怎麼跑起來。
