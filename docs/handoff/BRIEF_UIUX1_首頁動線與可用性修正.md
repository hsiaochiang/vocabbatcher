# BRIEF_UIUX1_首頁動線與可用性修正.md — UI/UX 稽核修正切片

> 交接合約：規劃層 → 執行層，2026-08-03。
> 背景：M3「考試與追蹤」全部完成後，負責人希望優先優化 UI/UX（首頁動線、整體操作直覺性），
> 規劃層用 `frontend-design-audit` 技能對全站頁面做了一輪完整稽核，本 BRIEF 是修正清單。
> 這不屬於 `STAGE_3_PLAN.md`/`STAGE_4_PLAN.md` 任何一片，是插入的品質優化切片。

## 開場指令（執行層開工先做）
1. 讀 `PROGRESS.md` 恢復脈絡。
2. 工作目錄為 `exam-vocab-batcher/`。

## 目標（一句話）
> 修正稽核報告列出的可用性問題，讓首頁動線更清楚、次要文字看得清楚、資料載入失敗有明確提示，整體操作更直覺。

## 任務（依優先度排序，全部要做）

### 1. 首頁動線重新設計（重大）
- **檔案：** `src/pages/HomePage.tsx`
- **問題：** 目前同時有「開始考試」（頂部，淡藍底強調）與「建立新批次」（底部固定，實心藍底強調）兩個視覺同等重要的主要按鈕，加上「成績歷史」「單字統計」兩張卡片、「繼續上次」、「歷史批次」，共 5 種入口擠在同一頁，新使用者不知道該先做什麼。
- **修法：**
  - 明確分區塊，加清楚的視覺層級：只保留**一個**視覺上最強的主要 CTA。建議邏輯：如果使用者**還沒有任何批次**（`batches.length === 0`），主要 CTA 是「建立新批次」（學習起點）；如果**已經有批次**，可以把「開始考試」拉高優先度（因為批次已經建好，接下來常態動作是考試/複習）。實作方式你可以自行決定用什麼條件切換，只要達到「同一時間畫面上只有一個最搶眼的主要動作」的效果即可。
  - 「成績歷史」「單字統計」改成視覺上明顯次要的呈現方式（例如文字連結列、小圖示＋文字的橫列，不要用跟主要卡片一樣搶眼的白色大卡片），避免跟主要動線搶焦點。
  - 不要拿掉任何功能入口，只調整視覺權重與排列順序。

### 2. 全站淺灰色文字對比度修正（重大）
- **問題：** 大量使用 Tailwind `text-gray-400`（對白底對比度約 2.9:1，低於 WCAG AA 4.5:1 標準）在有意義的文字上（空狀態說明、次要說明文字、時間戳記等）。
- **修法：** 全站搜尋 `text-gray-400`，逐一檢查：
  - 如果是**有意義的文字內容**（使用者需要讀懂的說明、提示、資料），改成 `text-gray-500` 或 `text-gray-600`。
  - 如果是**純裝飾性圖示**（例如 `chevron_right` 箭頭圖示、純視覺分隔），可以維持不變。
  - 檔案範圍包含但不限於：`HomePage.tsx`、`BatchBuilderPage.tsx`、`BatchHubPage.tsx`、`FlashCardPage.tsx`、`ExamSetupPage.tsx`、`ExamRunPage.tsx`、`ExamResultPage.tsx`、`ExamHistoryPage.tsx`、`WordStatsPage.tsx`。

### 3. 單字庫載入失敗要有明確錯誤畫面（重大）
- **檔案：** `src/store/AppContext.tsx`
- **問題：** `fetch(...vocab.cleaned.json)` 失敗時只有 `console.error`，`isLoading` 照樣設成 `false`，畫面呈現跟「資料是空的」一模一樣，使用者看不出是網路問題。
- **修法：**
  - 在 `AppContextValue` 加一個 `loadError: boolean`（或更豐富的錯誤資訊，你決定）。
  - `fetch` 失敗時設定這個狀態為 `true`。
  - 在會用到 `allWords` 的最上層（建議在 `HomePage.tsx`，或做成一個包住 `<Routes>` 的共用檢查）偵測到 `loadError` 時，顯示明確的「單字庫載入失敗，請檢查網路後點此重新載入」畫面，並提供一個重試按鈕（可以簡單用 `window.location.reload()`）。

### 4. 所有頁面統一顯示登入狀態（中等）
- **問題：** `BatchBuilderPage.tsx`、`FlashCardPage.tsx`、`ExamSetupPage.tsx`、`ExamRunPage.tsx`、`ExamResultPage.tsx` 的 `<Header>` 沒有帶 `rightSlot={<UserBadge />}`，只有 `HomePage`、`ExamHistoryPage`、`WordStatsPage` 有。使用者在考試/翻牌過程中看不到自己的登入狀態，考完才在結果頁發現沒登入、成績不會保存。
- **修法：** 在上述缺少的頁面的 `<Header>` 加上 `rightSlot={<UserBadge />}`，跟其餘頁面一致。**特別注意 `ExamSetupPage`**——這是使用者決定要不要考試「之前」看得到登入狀態的最後機會，務必補上。

### 5. 刪除批次改用自訂確認彈窗，取代瀏覽器原生 confirm()（中等）
- **檔案：** `src/pages/BatchHubPage.tsx`
- **問題：** 目前用 `window.confirm('確定刪除此批次？')`，樣式跟 App 其他地方不一致。
- **修法：** 做一個簡單的自訂確認 modal（可以參考專案裡其他彈出元件的風格，或新增一個輕量共用元件），文字改成更明確：「確定要刪除『{批次名稱}』嗎？裡面的翻牌進度也會一併刪除，無法復原」。不需要做得太複雜，一個置中彈窗＋兩個按鈕（取消/確定刪除）即可。

### 6. 考試作答頁對錯回饋加上圖示，不要只靠顏色（中等）
- **檔案：** `src/pages/ExamRunPage.tsx`
- **問題：** 選完答案後只用綠/紅底色分辨對錯，`ExamResultPage.tsx` 卻有用 `check_circle`/`cancel` 圖示，兩處不一致，且色盲/色弱使用者無法單靠顏色分辨。
- **修法：** 在 `ExamRunPage.tsx` 的選項按鈕裡，答對/答錯的選項旁加上跟 `ExamResultPage` 一致的圖示（`check_circle` / `cancel`）。

### 7. 考試設定頁防止「最小頁 > 最大頁」矛盾輸入（中等）
- **檔案：** `src/pages/ExamSetupPage.tsx`
- **問題：** `minPage`、`maxPage` 兩個輸入框沒有互相驗證，設反了只會在按下「開始考試」後得到一個模糊的「此頁數範圍內單字不足」提示，看不出真正原因。
- **修法：** 當使用者輸入導致 `minPage > maxPage` 時，即時做修正（例如自動把兩個值互換，或即時顯示提示文字），不要讓使用者一直猜不透為什麼出不了題。你決定用「自動互換」或「即時提示」哪種做法都可以，挑實作量小的即可。

### 8. 翻牌卡「上一張」補上進度儲存（輕微）
- **檔案：** `src/pages/FlashCardPage.tsx`
- **問題：** `goNext` 會呼叫 `persistIndex()`，`goPrev` 沒有呼叫，導致往回看的進度不會被存檔。
- **修法：** `goPrev` 也呼叫 `persistIndex(index - 1)`，跟 `goNext` 一致。

## 邊界（本切片不做）
- **不做**「BatchHubPage 兩個永遠顯示『即將推出』的功能格子」的處理——這是產品範圍決策（要接回現有的全域考試/統計功能、還是拿掉、還是補做批次專屬的錄音播放），需要負責人在規劃 M4 時定案，不是這次 UI/UX 微調能單獨決定的事。這次先不動 `BatchHubPage.tsx` 的 `features` 陣列內容。
- **不做**深色模式（`prefers-color-scheme`）——優先度最低，先不做。
- 不改考試出題邏輯、登入邏輯、Firestore 規則、路由選型、PWA 設定——這些都已經驗收通過，不要動到。
- 不新增任何新功能頁面，這次純粹是既有頁面的可用性/視覺修正。

## 驗收（負責人操作）
1. 開首頁，確認畫面上清楚看得出「現在該做什麼」，不會被 5 個入口卡片同時搶走注意力。
2. 隨便瀏覽幾個頁面（空批次列表、找不到考試資料等畫面），確認說明文字看得清楚，不會太淺看不清楚。
3. 模擬離線狀態（例如飛航模式）打開 App 第一次載入（若已有 PWA 快取可能看不到效果，這項若無法簡單測試可以跳過，用文字說明給你聽即可）。
4. 進「考試設定」頁，確認能看到自己有沒有登入（不用等考完才知道）。
5. 刪除一個批次，確認跳出來的確認畫面是 App 自己風格的彈窗，不是瀏覽器原生對話框。
6. 考一次試，答錯一題，確認選項上有勾勾/叉叉圖示，不是只有顏色。
7. 進「考試設定」，故意把最小頁設得比最大頁大，確認有合理的提示或自動修正，不會得到一個看不懂原因的錯誤。
8. 翻牌卡往回看幾張，關閉分頁重開，確認進度是你最後看到的那張，不是跳回去。
9. iPhone Safari、Android Chrome 各測一次整體操作順不順。
10. `npm run lint`、`npm run build` 通過。
