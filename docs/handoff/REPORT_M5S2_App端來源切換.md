# REPORT_M5S2_App端來源切換.md

> 執行層收工報告  
> 日期：2026-08-04  
> 範圍：M5-S2 App 端會考／學測來源切換

## 使用者現在能做什麼

- 首頁可以在「會考」與「學測」兩份單字庫之間切換。
- 選「學測」後，批次建立器只會顯示學測單字，可依學測頁碼一鍵建立批次。
- 學測批次進入翻牌卡、練習測驗時，只會使用學測單字。
- 切回「會考」後，首頁批次歷史只顯示會考批次，不會把學測批次混進來。
- 成績歷史與單字統計會依目前來源篩選；新的錯誤率統計用 `{來源}__{單字}` 當 Firestore 文件 ID，避免會考／學測共同單字互相污染。

## 本次改了什麼

- 新增 `VocabSource = 'cap' | 'gsat'`，會考讀 `data/vocab.cleaned.json`，學測讀 `data/vocab.gsat.cleaned.json`。
- `AppContext` 新增來源狀態，會記在瀏覽器 `localStorage` 的 `vocabSource`；未設定時預設會考。
- `Batch` 新增 `source` 欄位；舊批次沒有 `source` 時一律視為會考，避免既有資料壞掉。
- 首頁新增「會考／學測」切換，批次歷史與繼續學習只顯示目前來源。
- 批次建立器、批次 Hub、翻牌卡、練習測驗、成績歷史、單字統計都接上來源判斷。
- `examResults` 寫入 `source`；舊成績沒有 `source` 時視為會考。
- `wordStats` 文件 ID 改為 `{source}__{word}`，文件內容也寫入 `source`；舊統計沒有 `source` 或舊 ID 時視為會考。

## 風險與留痕

- 發現學測資料仍有少數 `source_page = 0`。App 載入時改為只保留大於 0 的整數頁碼，避免畫面出現教材上不存在的「第 0 頁」。
- 這個處理沒有改資料檔；受影響單字仍可搜尋與手動勾選，只是不會出現在頁碼按鈕與頁碼範圍考試中。
- 已記錄在 `docs/planning/DECISIONS.md`：`2026-08-04　M5-S2 App 載入時忽略非正整數頁碼`。

在 `exam-vocab-batcher/` 執行：

- `npm.cmd run lint`：通過
- `npm.cmd run build`：通過（仍有既有 Vite chunk size warning，非本片新增錯誤）
- `npm.cmd run test:e2e`：11 passed

新增的 Playwright 測試覆蓋：

- 從首頁切到學測，批次建立器顯示 1640 筆學測資料。
- 搜尋 `splendor` 可在學測資料找到，切回會考後找不到。
- 建立 `批次 #1（學測第 1 頁）` 後，翻牌卡顯示學測第 1 頁單字。
- 從學測批次進入練習測驗，檢查考試狀態帶著 `source = 'gsat'`，且產生的題目都屬於學測第 1 頁。
- 回首頁切回會考後，學測批次不會出現在會考批次歷史。

## 負責人白話驗收步驟

1. 打開 App 首頁，確認上方看得到「會考／學測」切換。
2. 點「學測」，進入建立批次，確認標題是「學測批次建立器」，清單筆數約 1640。
3. 搜尋 `splendor`，確認找得到；點第 1 頁建立學測批次。
4. 進入翻牌學習，確認看到的是學測單字，例如 `accord`。
5. 進入練習測驗，選幾題作答，確認題目不是會考常見的 `about`、`after` 那批字。
6. 回首頁切回「會考」，確認剛剛建立的學測批次不會出現在會考批次歷史。
7. 登入後各做一次會考與學測考試，再進「成績歷史」「單字統計」，確認切換來源時資料分開顯示。
