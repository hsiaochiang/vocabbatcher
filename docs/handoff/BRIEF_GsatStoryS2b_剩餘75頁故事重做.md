## 目標（一句話）
> 用 Minecraft 主題故事，把學測單字庫剩下 75 個頁碼（第 1~15、21~80 頁，共 1539 個目標單字）**逐頁真正手寫**成自然、適合國小剛升國一學生閱讀的故事，品質要跟第16~20頁試行版同一水準，不能用固定模板套字取巧。

## 現況（可直接重用）

- 單字資料來源：`exam-vocab-batcher/public/data/vocab.gsat.cleaned.json`。依 `source_page` 分組取得每頁單字清單，這部分程式邏輯（讀檔、分組、寫最終 JSON 檔案）可以寫成腳本沒問題——**這次要禁止的，是「句子內容本身」由程式邏輯/模板陣列自動產生**，讀檔/分組/組裝/寫檔這些純機械性的 I/O 工作用腳本處理完全沒問題。
- 資料結構範本（schemaVersion 2，完全比照 `stories_pilot_16_20.json`）：
  ```jsonc
  {
    "schemaVersion": 2,
    "stories": [
      {
        "id": "gsat-p<頁碼>-minecraft",
        "source": "gsat",
        "page": <頁碼 number>,
        "theme": "minecraft",
        "wordList": ["這一頁全部單字，跟 vocab.gsat.cleaned.json 的 word 欄位完全一致"],
        "generatedAt": "<ISO時間字串>",
        "sentences": [
          {
            "index": 0,
            "text": "英文句子，包含這句對應的目標單字，語意通順、搭配自然",
            "zh": "台灣慣用語中文翻譯，目標單字用全形括號標註英文原文",
            "targetWords": ["這句對應的目標單字，通常1個，最多不超過3個"]
          }
        ]
      }
    ]
  }
  ```
- QA 腳本：`output/story/gsat/qa_check.py`（或上一輪新增的 `qa_check.mjs`，若本機沒有 Python 就用這個）可以繼續沿用做「單字覆蓋」「中文括號標註」這兩項基本檢查，但**這兩項通過不代表內容合格**，這次額外要加一項「重複句型」檢查（見下方任務3）。

## 任務

1. **逐頁真正手寫故事（第 1~15、21~80 頁，共 75 篇）**：
   - **禁止用固定模板陣列/樣板句型輪流套字。** 具體來說：不能像上一輪那樣寫 5~10 句固定句型（例如「Alex found the glowing word "X" on a sign」），然後迴圈把不同單字代入同一組句子——這樣寫出來的 1539 句裡，扣掉單字本身，其餘文字幾乎一模一樣，這是不合格的做法，這次會被規劃層逐句核對抓出來。
   - 每個單字要真正依照它自己的詞性、語意，構思一個獨立的、有畫面感的句子，讓這句話本身能傳達這個字的意思（不是只有「牌子上寫著這個字」這種空殼句），比照試行版本的寫法，例如試行版第16頁：「Steve's insight about ocean currents helped them find the fastest route.」（用 insight 表達「洞察力」的實際語意，不是單純把字塞進句子）。
   - 每頁故事要有連貫的情節（例如試行版第16頁是「潛入海底神殿探險」、第18頁是「準備村莊慶典」），不是1539個互不相干的單句拼接。
   - 如果覺得一次寫完75頁份量太大，**可以分批進行**（例如每次專心寫10~15頁，寫完自我檢查沒有重複句型再繼續下一批），不用一次做完，但每一批、每一句都要是你自己構思的內容，不能為了省力寫腳本套模板。
   - 學測單字比會考抽象（例如 subsequent、compassionate、democratic），這些字更難自然融入，正是最考驗有沒有真的用心寫、還是隨便套模板的地方，這次規劃層會特別挑抽象字集中的頁碼核對。
   - 每句都要有 `zh` 中文翻譯（台灣慣用語），目標單字用全形括號標註英文原文，格式比照試行版本。中文句子也**不能是同一句模板套不同單字**，要跟著英文句子的實際內容翻譯。
   - `wordList` 裡的字要跟 `vocab.gsat.cleaned.json` 該頁的 `word` 欄位完全一致。

2. **重複句型自我檢查（這次新增，用來防止再犯上一輪的錯）**：
   - 完成後，寫一個檢查腳本（或擴充 `qa_check.py`/`qa_check.mjs`）：把每個句子的目標單字用固定佔位符（例如 `___`）取代後，統計「去除單字後的句子骨架」在全部 1539+101 句裡重複出現的次數，**任何一種句子骨架不能重複超過 5 次**（合理的自然重複，例如「Alex 決定...」這種開頭偶爾出現沒關係，但不能像上一輪那樣同一套骨架用了150幾次）。
   - 把這項檢查的結果（最常見的幾種句型骨架、各自出現次數）寫進報告，讓規劃層能一眼看出有沒有變相模板化。

3. **QA 驗證（沿用上一輪的兩項基本檢查）**：
   - 單字覆蓋：每頁 `wordList` 的字都要出現在該頁故事英文文字裡。
   - 中文括號標註：每個 `targetWords` 都要能在對應句子的 `zh` 字串括號裡找到。
   - QA 沒過的頁面不要放進最終的 `stories.gsat.json`（partial-ship-and-backfill 原則）。

4. **合併輸出**：
   - 把試行的 5 頁（`stories_pilot_16_20.json`，內容不要改）與這片新生成的 75 頁，合併成完整版 `output/story/gsat/stories.gsat.json`（80 頁或扣除沒過頁面後的實際頁數）。
   - 一樣先不要複製進 `exam-vocab-batcher/public/data/`。

5. **報告裡必須附內容樣本**：
   - **在收工報告裡，完整貼出至少5頁的實際內容**（英文+中文全部句子，不是摘要），規劃層指定：第1、21、40、60、80頁，加上你自己覺得寫得最有把握的1頁。這樣規劃層不用另外開檔案就能核對品質，這是這次特別要求的（上一輪報告完全沒有附實際內容，只有統計數字，這是規劃層沒能及早發現模板化問題的原因之一）。

## 驗收（負責人操作）

1. 規劃層會先看報告裡附的5頁實際內容，確認不是模板套字，語意通順、有連貫情節。
